# A1 isolation and preview-boundary evidence

Date: 2026-09-14

## Scope and gate interpretation

This evidence covers REQUIREMENTS §16 Phase A gates 2 and 11, REQ 48, and
IMPLEMENTATION_PLAN §5 **Database enforcement** for the routes implemented
through T5/T6. Real order, transition, attachment, and file-route isolation
remains assigned to T16/T23 when those routes exist; this evidence does not
claim those later checks.

Supabase token verification is the sole external boundary replaced by a
deterministic verifier. The HTTP routers, authorization policy, database
stores, restricted runtime role, RLS policies, credential bootstrap, and
machine registry are the real implementations.

## Isolation suite

`apps/backend/tests/isolation.spec.ts` uses two synthetic workspaces and tests:

1. Altered staff workspace path IDs are denied, and foreign membership and
   service-credential fixture IDs return not found without changing the foreign
   records.
2. A membership removed behind an otherwise valid live session is denied on
   the next request.
3. Expired/forged staff bearer credentials and forged/revoked website service
   credentials are denied.
4. Body/Host/Origin workspace claims cannot override the website credential's
   workspace; a forged role header cannot escalate a viewer on the existing
   protected service-credential action.
5. Missing database context sees no tenant rows, and sequential tenant
   transactions on the same one-connection pool do not reuse `SET LOCAL`
   workspace context.
6. The server-only machine registry rejects provider-account and expected-
   workspace confusion even with a signature valid for another mapping.

## CI enforcement

- `pnpm run check:preview-isolation` validates
  `docs/DEPLOYMENT_INVENTORY.json`. A provisioned preview credential must map to
  a same-kind preview/non-production resource identified by a SHA-256
  fingerprint of its provider-issued immutable ID. Name-only resources,
  missing bindings, and fingerprints reused from production fail. The current
  inventory accurately records all three preview deployments as not provisioned
  with no credentials; it must be updated in the provisioning change.
- `pnpm run check:frontend-db-boundary` runs the repository ESLint boundary over
  `apps/admin` and `apps/site-1`. Existing tooling fault cases prove static,
  subpath, dynamic, relative, CommonJS, and type-only imports of
  `@canadian-plans/db` fail.
- Both checks are named mandatory steps in `.github/workflows/ci.yml`, before
  compilation and tests. CI first migrates disposable PostgreSQL and exports
  both database-test opt-ins, so the isolation suite cannot silently skip in
  CI.
