# Category Airport + Compare visual evidence

This evidence accompanies the two isolated design-preview routes:

- `/pre-arrival-sim/toronto-pearson` from Figma desktop `186:509` and mobile `256:988`.
- `/compare/rogers-vs-fido` from Figma desktop `182:2` and mobile `255:516`.

The original Figma renders are saved at native 1440px and 390px widths in `figma-*.png`. Browser renders and section crops are saved as `browser-*.png`, `airport-*.png`, and `compare-*.png`. `verification.json` is generated by `apps/site-1/scripts/verify-category-airport-compare.mjs` against the shared preview server; it records responsive overflow checks, runtime errors, axe results, selected keyboard interactions and visible exported-asset geometry.

The airport plan fixtures link to the existing preview checkout with supported plan IDs. The Rogers/Fido prepaid price/data examples remain `previewOnly` content and link to the corresponding plan listings; they do not enter the mismatched pre-arrival checkout. Carrier prices, plan claims, bylines and testimonial copy remain preview fixtures pending approval.

`node-asset-map.json` maps source frames and exported/reused assets. Exact duplicate SVG exports are reused from the component design library; the unique airport handset/perforation exports live under `apps/site-1/public/design/category-airport-compare/`.

Central token proposals were merged into `packages/ui/src/styles/canadian-plans.css`; this file is retained as a record of the category-specific token set.

The comparison hero follows the source frame's 48px mobile heading, 20px lede, 18px prices, 16px spec sheet, gray breadcrumb band/checks, equal-width spec columns, and source spec values. Its source-yellow eyebrow is intentionally rendered in the shared blue accent because yellow on the pale-lemon hero background does not meet readable contrast; this is the deliberate accessibility variation. A single preview-only disclosure below the comparison cards keeps carrier fixture values clearly labeled as unapproved examples.
