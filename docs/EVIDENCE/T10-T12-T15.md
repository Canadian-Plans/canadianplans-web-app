# T10 / T12 / T15 verification

Date: 17 September 2026

## Scope

Catalogue sync (T10), order submission and admin processing (T12) and the
transactional outbox runner (T15), plus the review repairs listed below
(codes G12–G30; G15, G17 and G20 were handled in earlier changes and required no
further work here, and this evidence document is itself G18) and the schema
change the review required. The catalogue, order and outbox paths are
implemented and green on a frozen tree; this document records the review's
correctness repairs and the verification evidence obtained for them.
Production publishing, dispatch and activation remain disabled behind
unresolved inputs (see "TEST-only policies in force" below).

## Correctness repairs

- G12 — added `listDrainableEvents` and `CatalogueService.drainEvents`: one
  bounded pass over the workspace's pending events plus failed events still
  below the attempt bound, in deterministic `createdAt, id` order, with each
  event's failure recorded and skipped so one poison delivery cannot block the
  queue. T10B schedules it with `reconcile` under the existing `reconcile:run`
  scope.
- G13 — provider adapters are an explicit, non-production opt-in
  (`OUTBOX_ADAPTERS=fake`). A production or unset deployment registers handlers
  that fail permanently with `provider_not_configured`, so a claimed job is
  recorded as failed in admin rather than completing under a fake provider id.
- G14 — request-error logging is PII-safe (`logRequestError`), and the orders
  route returns `503` only for connection-level failures and `500` otherwise,
  instead of misreporting an application error as a provider outage.
- G16 — a completed-idempotency-key retry is bounded by
  `ORDER_RETRY_WINDOW_MS` (24 hours) measured from `completedAt`; outside the
  window the caller receives `draft_expired` rather than a replayed order.
- G19 — recorded the catalogue/order/outbox concurrency and identity decisions
  in `docs/ADR/0003-catalogue-orders-outbox.md`.
- G21 — a correctly signed but malformed webhook body (invalid JSON or an
  invalid payload shape) now returns `400 invalid_request` instead of falling
  through to a generic failure.
- G22 — webhook registry entries require `actorId`; the verified machine actor
  is persisted as `catalogue_sync_events.actor_id` (migration
  `0014_concerned_karen_page.sql`) and reused by every later inbox and sync
  write, so drain attribution is stable and never the event id or a random UUID.
- G23 — each handler runs under a per-handler abort timeout, recorded as
  `uncertain` with `handler_timeout` because the provider may already have
  accepted the work; a run deadline stops the runner claiming new batches while
  still handling and recording jobs already claimed under a lease.
- G24 — the `ORDER_OPERATIONAL_TRANSITIONS` switch is TEST-only and is ignored
  when `NODE_ENV=production`, so it can never authorize a real dispatch or
  activation.
- G25 — an operator requeue of a definitively failed job preserves the previous
  attempt's provider evidence (`provider_id`, `outcome`) and resets only the
  attempt and lease state.
- G26 — `reconcile` reads one `listPublished()` snapshot for the whole pass
  (no per-product N+1 listing), and its actor is required and registry-backed:
  the scheduler entry is resolved through
  `schedulerForWorkspace(workspaceId, 'reconcile:run')`, and the manual command
  fails closed with `reconcile_actor_unavailable` when no single non-revoked
  entry matches.
- G27 — added Sanity catalogue adapter unit tests and registered the adapters
  project with its own `vitest.config.ts`.
- G28 — site-1 catalogue revalidation invalidates a `plan:<productKey>` cache
  tag in addition to the `/plans` index.
- G29 — the runbook's command target `backend` was verified correct as written;
  no change required.
- G30 — the staging cron check cannot run without a dedicated staging Vercel
  project. Recorded as a pending external check below, not a pass.
