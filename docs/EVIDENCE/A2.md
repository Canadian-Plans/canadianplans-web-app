# A2 order-journey and pricing-integrity evidence

Date: 2026-09-18

## Scope and gate interpretation

This evidence covers REQUIREMENTS §16 Phase A **gates 3 and 4** — the customer
order journey and CMS-price integrity — end to end:

- **Gate 3** — partial leads resume safely; repeated final submissions create
  one order; failed persistence never shows success; the terms version is
  recorded.
- **Gate 4** — publishing a CMS price changes new quotes while existing orders
  keep their snapshot; an unverifiable price cannot create a priced order.

The suite proves the full spine — **browser → lead → quote → order → admin
processing** — plus the launch-critical negative cases the task enumerates. It
uses **synthetic offers that require no documents** (a `documentChecklist` of
`['passport']` records the step without an upload; uploads arrive in T17).
**Partnered activation and document enforcement are out of scope here and are
proved in T23.** OPEN_INPUTS #15 (transition prerequisites) is likewise not in
scope; operational transitions stay disabled.

## What is real, and the bounded test seams

The suite runs against the real backend application booted by
`apps/backend/tests/e2e/harness.ts`: real HTTP routes, real Postgres with RLS,
real lead/quote/order transactions, real idempotency and reference generation,
the real staff authorization store, and the real outbox runner and job store.
The **admin-processing leg is the real `/api/v1/staff` API** on that same
backend.

The seams that cannot exist in production, and nothing more:

1. A stub published-catalogue provider (same `SanityCatalogue` interface as the
   real adapter), so the journey needs no live Sanity project. It can be armed
   to fail, have a price changed, or have an offer withdrawn — each still
   applied to published state through the **real reconcile path**.
2. An admitting bot check (the production Turnstile verifier rejects public test
   secrets).
3. Raised website rate-limit thresholds — the real DB-backed limiter still runs
   on every request; only the numbers move.
4. A stub staff-session verifier admitting **one** seeded, fully-privileged
   (owner, aal2) staff actor for a fixed bearer token. Everything past the
   verifier — authorization, RLS, order/job queries — is genuine. Production
   uses `SupabaseStaffSessionVerifier`.
5. A harness-owned outbox runner whose **email** handler can be armed to fail
   permanently. The analytics handler and the job store are the real ones.

This is not proof of hosted Turnstile, hosted Supabase Auth/MFA, or a live
Sanity project.

## OPEN_INPUTS #14 — production priced checkout stays gated

The quote-withdrawal timing decision is unresolved. The backend encodes this as
a first-class `unresolved` policy: `OrderService.submit` and
`CatalogueService.createQuote` both short-circuit to `checkout_disabled`
(`priced_checkout_disabled`, HTTP 503) whenever the policy is `unresolved`.
Test 5c drives a full journey under that policy and shows the storefront cannot
produce a priced quote or order. Both selectable TEST policies
(`honour_until_expiry`, `immediate`) are exercised (5a, 5b). This is TEST-policy
coverage, not evidence that the production decision has been made.
